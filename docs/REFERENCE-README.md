# Magikstudio — studio site

Local project: `magikstudio`, cloned from `git@github.com:oettaib/indie-core-dev.git`.
The upstream site content and deployment configuration below are retained for the next adaptation step.

Original marketing site for [Indie Core Dev](https://www.indiecore.net), a one-person game studio in
France. Static site generated by a small Node script, deployed to Cloudflare Workers (static assets).

It also hosts the privacy policy for every game. **Those URLs are referenced from Google Play
Console listings — they must not break.** Old Blogger paths are 301-redirected to their new
homes (see `_redirects`, generated by `build.mjs`).

Working on it — as a person or with a coding agent? Start with
[AGENTS.md](AGENTS.md): the conventions and the handful of things that must not break.

## Stack

No framework. `build.mjs` reads content and templates and writes `dist/`.

```
_source/play-data.json      Google Play metadata (descriptions, category, updated date)
_source/legacy/*.txt        privacy policy source text, one per game
_source/indexnow-key.txt    IndexNow ownership key (public; copied to dist/<key>.txt)
_source/seo-watch.json      search ledger — Google and Bing observations, open findings
src/styles.css              the whole stylesheet (inlined into each page at build time)
src/app.js                  reveals, galleries, lightbox, mobile nav
public/assets/games/        game icons and screenshots (JPEG; WebP generated at build)
public/assets/fonts/        subset webfonts (committed — see "Regenerating assets")
public/assets/og/           social preview images (committed — see below)
build.mjs                   generator: pages, sitemap, robots, _redirects, _headers
scripts/verify.mjs          build verification — dead links, images, meta, redirects
scripts/lighthouse-check.mjs Lighthouse budget gate
scripts/seo-ping.mjs        IndexNow + Search Console + Bing submit, and an index-status report
scripts/seo-watch.mjs       search watcher — what changed across both engines, and what to do
scripts/bing-api.mjs        Bing Webmaster Tools API client, shared by the two above
scripts/serve.mjs           local server that mirrors Cloudflare (brotli, cache, redirects)
```

## Quick start

```bash
nvm use            # Node 22 (see .nvmrc)
npm ci
npm run dev        # build + serve on http://localhost:4321
```

`cwebp` must be on your PATH for the build (`brew install webp`).

## Before you push

```bash
npm run check      # build + verify — the same gate CI runs
```

## Branching and deploys

See [CONTRIBUTING.md](CONTRIBUTING.md). Short version: branch off `main`, open a PR, get a
preview URL, squash-merge. `main` deploys to production automatically.

| Event | What happens |
| --- | --- |
| PR opened / updated | build → verify → Lighthouse budget → Cloudflare preview, URL posted on the PR |
| Merge to `main` | build → verify → Lighthouse budget → production deploy |
| After a production deploy | SEO ping — IndexNow submit, sitemap resubmit, index-status report |
| Daily, 06:17 UTC | SEO watch — compare against the ledger, raise what changed |

Deploy jobs depend on the gates, so a failing build or budget never ships.

## Regenerating assets

Two scripts need tooling CI deliberately does not install. Run them locally and commit the
output.

```bash
npm run assets:og      # social preview cards — needs Chrome + ImageMagick (`brew install imagemagick`)
npm run assets:fonts   # re-download and subset webfonts — needs Python + fontTools
```

## One-time setup

### 1. Cloudflare Worker

Create a Worker named **`indie-core-dev`** via **Workers & Pages → Create → Workers →
Upload assets**. This repo deploys to it with Wrangler from GitHub Actions, not via
Cloudflare's own Git integration, so the build/verify/Lighthouse gates run first.

### 2. Scoped API token

Cloudflare dashboard → **My Profile → API Tokens → Create Token → Custom token**:

| Setting | Value |
| --- | --- |
| Template | **Edit Cloudflare Workers** |
| Account resources | Include → your account |
| Zone resources | Include → `indiecore.net` |
| TTL | set an expiry and diarise the rotation |

The template selects exactly the permissions a Worker deploy needs. Do not use a Global API
Key — it can do anything on the account and cannot be scoped.

### 3. Repository secrets

**Settings → Secrets and variables → Actions**:

| Secret | Where to find it |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | the token from step 2 |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare dashboard URL, or Workers & Pages → Account details |

### 4. Environments

**Settings → Environments** → create `production` and `preview`. On `production`, restrict the
deployment branch to `main`. Add yourself as a required reviewer if you want deploys to pause
for approval.

### 5. Branch protection

**Settings → Rules → Rulesets** → new branch ruleset targeting `main`:

- Restrict deletions, block force pushes
- Require a pull request before merging
- Require status checks: **`Build & verify`** and **`Lighthouse budget`**
- Require branches to be up to date before merging

### 6. Search Console and Bing (optional, but the SEO watch needs one of them)

IndexNow works with no setup, and it is what tells Bing a page changed. What needs
credentials is the answer coming back.

| Secret | Buys you |
| --- | --- |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Search Console: sitemap submit, per-URL index status, query performance |
| `BING_API_KEY` | Bing Webmaster Tools: per-URL crawl records, crawl errors, query stats |

The SEO ping skips whichever half is missing. The SEO watch runs on either, and skips
the other rather than reading its silence as a regression.
[docs/seo-automation.md](docs/seo-automation.md) has both walkthroughs — including why
Google's Indexing API is not the answer here, and why the Bing API retirement headline
does not apply to the endpoint this repo calls.

### 7. Domain

In the Worker → **Settings → Domains & Routes**, add `indiecore.net` and `www.indiecore.net`.
Point the DNS at Cloudflare and remove the Blogger records once the site is verified live.

Check that the legacy paths still resolve after cutover:

```bash
curl -sI https://www.indiecore.net/p/privacy-policy-for-word-slot.html | head -2
# expect: HTTP/2 301  +  location: /privacy/word-slot/
```

## Security notes

- All GitHub Actions are pinned to commit SHAs, not tags — a tag can be moved to point at
  malicious code, a SHA cannot. Dependabot updates them weekly.
- Workflows run with `permissions: contents: read`; only the preview job gets
  `pull-requests: write`, to post its comment.
- `actions/checkout` runs with `persist-credentials: false` so no token is left on disk.
- Deploys are skipped for pull requests from forks, which cannot read repository secrets.
